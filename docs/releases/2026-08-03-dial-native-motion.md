# 다이얼이 웹처럼 보이던 이유를 고쳤습니다

## 한눈에 보기

James 의 보고는 한 문장이었습니다 — **"웹이라 가벼움."** 앱이 아니라 웹페이지를 쓰는 느낌이 든다는 뜻이었고, 전 표면을 감사한 결과 원인은 화려한 효과의 부재가 아니라 **화면이 바뀌는 방식** 두 곳에 있었습니다.

- **화면 전환**이 크로스페이드였습니다. 두 화면이 동시에 반투명해지면서 14px — 화면 폭의 3% — 움직입니다. 그건 이동이 아니라 떨림입니다.
- **덱이 닫힐 때** 애니메이션이 아예 없었습니다. 전체화면 검은 판이 크림색 탭 위에서 한 프레임에 사라집니다.

둘 다 고쳤습니다. 화면은 이제 **불투명하게 방향을 갖고 밀려** 들어오고, 나가는 화면은 반대쪽으로 짧게 물러나며 어두워집니다 — 사라지는 게 아니라 밑으로 들어가는 것으로 읽힙니다. 덱도 같은 문법을 씁니다.

**전부 `?mnav=1` 플래그 뒤에 있습니다.** 플래그를 켜지 않은 사용자에게는 바이트 단위로 이전과 동일합니다.

## 사용자 관점 변경점

| | 전 | 후 |
|---|---|---|
| 화면 이동 | 두 화면 반투명 겹침 + 14px | 불투명 방향 푸시, 340ms |
| 뒤로 가기 | 앞으로 가기와 구별 안 됨 | 왼쪽에서 들어옴 |
| 덱 닫기 | 하드컷 | 방향을 갖고 퇴장 |
| 목록 오버스크롤 | 앱 셸까지 고무줄처럼 끌림 | 각 목록 안에서 멈춤 |
| 썸네일 롱프레스 | iOS "이미지 저장" 시트 | 뜨지 않음 |

## 왜 이렇게 바꿨나

수치는 iOS 자신의 것을 따랐습니다 — 도착은 급하게 감속하고(`cubic-bezier(.32,.72,0,1)`), 퇴장은 가속해 빠집니다(`cubic-bezier(.4,0,.6,1)`). 340ms.

포그라운드 탭에서 rAF 로 실측한 값:

- 푸시 390 → 0, 감속 약 344ms
- 이탈 −28% + 밝기 .84
- 팝 텔레포트 8ms, 진입 −109px
- 덱 1705 ↔ 0

## 배포 중 잡은 실버그 하나

설계 노트(#1452)의 사실을 전건 재검증하다가 **팝이 오른쪽에서 들어오고 있는 것**을 발견했습니다. 뒤로 가기가 앞으로 가기와 똑같이 보였다는 뜻입니다.

원인은 `void offsetWidth` 였습니다. 흔히 "시작 위치를 강제로 커밋한다"고 알려져 있지만, **transition 이 활성인 동안에는 커밋이 아니라 그 지점부터의 재타게팅**입니다. 수정은 텔레포트가 필요한 그 recalc 에만 `transition:none` 을 걸었다 푸는 것.

**기기에 올리기 전에 잡혔습니다.** 설계안을 그대로 믿지 않고 사실을 하나씩 되짚은 것이 값을 했습니다.
