# 2026-07-30 — 다이얼 가로보기 정리

## 한눈에 보기

가로로 돌려서 영상을 볼 때 화면이 한쪽으로 밀리고 잘려 나가던 문제를 끝냈습니다. 조그휠이 실제로 영상을 넘기게 됐고, 아래 바가 "이 주차 20편 중 몇 번째"를 뜻하게 바뀌었습니다. 가로에서 유튜브 자체 버튼이 눌리지 않던 것도 풀렸습니다.

## 사용자 관점 변경점

- **가로 영상이 화면 한가운데에 놓입니다.** 밀리지도, 잘리지도 않습니다. 유튜브 앱에서 전체보기를 눌렀을 때와 같은 크기·같은 위치입니다.
- **조그휠을 돌리면 영상이 넘어갑니다.** 천천히 돌리면 한 편씩, 빠르게 돌리면 가속이 붙어 여러 편을 건너뜁니다. `◀◀ ▶▶` 는 정확히 한 편씩.
- **아래 바가 이번 주 라인업입니다.** 20편이 20칸으로 나뉘어 있고 지금 몇 번째인지 보여줍니다. 영상 안에서의 재생 위치는 유튜브가 이미 보여주므로 중복을 없앴습니다.
- **바가 영상 아래 가장자리에 붙습니다.** 영상을 가로지르지 않고, 유튜브 버튼·조그휠이 사라질 때 같이 사라집니다.
- **가로에서 유튜브 버튼이 눌립니다.** 재생·자막·설정·전체화면 모두.
- **탭한 뒤 화면이 죽어 보이지 않습니다.** 영상이 시작되기 전까지 그림 위쪽에 얇은 선이 흐릅니다.
- **썸네일이 회색 상자로 뜨던 것**을 고쳤고, 회선이 느리면 가벼운 썸네일을 씁니다.
- **세로에서 가로로 돌렸다 돌아와도** 위아래가 잘리지 않습니다.

## 왜 바꿨나 (측정 근거)

가로 쏠림은 **홈 화면에 설치한 앱에서만** 나타나고 브라우저 탭에서는 없었습니다. 그 차이가 원인을 특정했습니다 — 설치 앱에서는 iOS 가 노치 안전영역 값을 유튜브 프레임 안까지 전달하고, 플레이어가 그만큼 그림을 밀어 그립니다.

기기 실측: 보정값 `-1 × env(safe-area-inset-left)` 를 걸었을 때 그림이 **정확히 129 device px**(315 → 186) 움직였고, 실제 쏠림도 129 였습니다. 59 CSS px — 이 기종 가로 안전영역 표준값입니다.

보정으로는 풀 수 없었습니다. 플레이어가 그 값을 반영한 레이아웃과 아닌 레이아웃을 오가는데, 다른 출처 프레임 안이라 어느 쪽인지 물어볼 방법이 없습니다. 그래서 **가로 재생 동안만 안전영역 자체를 끄는** 방식으로 원인을 제거했습니다. 화면 손실은 없습니다 — 그림이 높이로 제한되기 때문에 782×440 그대로입니다.

## 재사용 가치가 있는 측정치

- `YT.Player.setSize()` 는 iframe 의 width/height **속성**만 쓴다 → author CSS 에 짐. `setSize(300,200)` 후에도 782×440 유지. 임베드를 재배치시키려면 **상자를 실제로 바꿔야** 한다.
- 복원 콜백에 `requestAnimationFrame` 금지 — 페인트 없는 동안 throttle 되어 넛지가 고착(956 뷰포트에서 955 실측). `setTimeout` 사용.
- 유튜브 썸네일: `hq` 480×360 · `sd` 640×480 = **4:3**(검은 띠 구움), `mq` 320×180 · `maxres` 1280×720 = 16:9. maxres 부재 시 **200 + 120×90 회색 플레이스홀더**를 주므로 CSS 다중 url 로 못 거른다.
- 컬러웨이 토큰은 `.device` 에만 있어 `#curDeck`/`#ytSheet`/`.toast` 에 도달하지 않았다 → 진행바 채움이 계속 투명이었다. `:root` 에 기본 컬러웨이 선언 + CI 게이트 추가.
