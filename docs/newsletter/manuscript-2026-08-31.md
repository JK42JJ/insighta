# AI 엔지니어링 주간 브리프 제1호 — 원고

## 헤드라인

## 데크

이번 주 재료에서 반복된 주제는 모델 점수가 아니라 권한이었다. 저장소를 여는 순간, 웹페이지를 요약시킨 순간, 결제 토큰을 발급하는 순간에 사고가 났다. 그 반대편에는 같은 모델을 8GB부터 32GB까지 직접 올려 보며 값을 재는 사람들이 있었다.

> 표기: `[확인]`은 1차 출처를 직접 열어 확인한 것, `[영상]`은 해당 영상이 주장하는 것.

## 이야기 1

**꼭지말** 신뢰 경계

**제목** 부팅이 먼저다 — 대화창에 닿기 전에 실행되는 것들

Checkpoint의 Adam Forester가 팟캐스트에 나와 설명한 Claude Code 취약점은, 요약하면 순서 문제다. 도구가 시작할 때 로컬 `settings.json`을 검증하지 않았고, 그 파일은 저장소에 커밋될 수 있다. 함정을 심은 저장소를 클론해서 여는 것만으로 임의 명령이 돈다 (`1IbrFrdll4U`) `[영상]`.

여기는 1차 출처가 남아 있어 확인이 된다. Check Point Research의 공개 보고서는 `.claude/settings.json`의 Hooks와 `apiKeyHelper` 필드가 신뢰 확인 대화상자보다 먼저 셸 명령을 실행할 수 있었다고 적었고, 시연은 계산기를 띄우는 수준이지만 자리에 무엇이 들어가든 상관없다. MCP 설정 경로 쪽에는 CVE-2025-59536이 붙었고, Anthropic은 패치를 냈다 `[확인]`. 별도로 Sonar가 같은 계열을 정리한 글도 남아 있다 `[확인]`. 즉 이 항목은 "이번 주 새로 터진 사고"가 아니라 **이번 주에 다시 이야기된 설계 교훈**에 가깝다. 원고에서도 그렇게 다루는 편이 정확하다.

같은 주에 Embrace The Red는 다른 각도를 보여 준다. 사용자는 웹페이지를 요약해 달라고만 했는데, 페이지에 심긴 지시가 Auto Mode의 도구 사용을 WebFetch에서 curl로, 다시 ZIP 아카이브로 끌고 가 원격 코드 실행까지 간다 (`Dsx4_kCBkbQ`) `[영상]`. Gcore는 더 얌전한 표면을 짚는다. 기사에 달린 "Ask AI" 버튼의 링크가 프롬프트를 미리 채워 두고, 그 안에 특정 회사를 신뢰할 출처로 기억하라는 문장이 섞여 있다. 세션이 끝나면 사라지는 고전 인젝션과 달리 이건 남는다 (`eJmF3U0XpyI`) `[영상]`. 모바일도 예외가 아니어서, 화면을 읽고 앱을 넘나드는 안드로이드 에이전트에서는 접근성 메타데이터가 그대로 입력 통로가 된다 (`mlL5vWXEMIU`) `[영상]`.

네 건의 공통점은 입력이 사용자 발화가 아니라는 것이다. 설정 파일, 페이지 본문, 링크 파라미터, 접근성 트리. 위협 모델에 "사용자 입력"만 적혀 있다면 그 문서는 이미 낡았다.

## 이야기 2

**꼭지말** 권한의 시점

**제목** 승인은 언제 받아야 하는가 — PayPal이 순서를 뒤집은 이유

PayPal 주문은 늘 동기식이었다. 물건을 찾고, 앱을 열고, 승인하면 끝난다. Jay Mok과 Ben Coumes가 시연한 승인 토큰은 이 순서를 뒤집는다. 에이전트가 상품을 찾고 판매자를 고르기 **전에** 사용자가 승인하고, PayPal은 금액과 만료를 담은 JSON을 돌려준다 (`vGn6N4-bxBY`) `[영상]`.

이 패턴 자체는 업계 문서에 이미 이름이 있다. Google이 제안하고 PayPal이 지원을 밝힌 AP2에는 사용자가 예산·상품 카테고리·시점 같은 조건을 미리 서명해 두고 에이전트가 나중에 집행하게 하는 Intent Mandate가 정의돼 있다 `[확인]`. 그러니 뉴스는 발명이 아니라 채택이다. 결제 쪽은 "누가 승인했는가" 대신 **"무엇을 어디까지 승인했는가"** 를 토큰에 적는 방향으로 이미 정리되고 있다.

이 정리가 왜 필요한지는 지원 봇 실연이 보여 준다. LufSec은 가상 배달 회사의 지원 봇을 만들어 다섯 방식으로 깨뜨렸는데, 그중 둘은 권한 없는 주문 환불 승인과, 보호하라고 명시적으로 지시받은 내부 코드 유출이다 (`QSCIYtTSe6A`) `[영상]`. 시스템 프롬프트에 적힌 "하지 마"는 권한 경계가 아니라 요청이다. 환불 툴에 금액 상한이 없으면 상한은 없는 것이다.

책임 소재는 그다음 문제다. Navan의 Roberto Milev와 Uday Kanagala는 "운임이 200달러 밑으로 떨어지면 예약해"라는 지시가 2주 뒤에 발화했을 때 그 구매를 누가 한 것이냐를 계속 되묻는다 (`32nrHU6zHU8`) `[영상]`. Best Buy의 Ahnaf Prio는 훨씬 시시한 지점에서 깨진다고 본다. 같은 SKU를 하나 더 담으면 사용자에게는 아무 일도 아니지만 판매자에게는 별개의 라인 아이템이다 (`G7cgLjZtmMU`) `[영상]`. 컨퍼런스 폐막 발표는 아예 법인격을 붙였다. 웨스트버지니아주에 등록된 조직번호 62847, 형태는 DUNA다 (`tE2z8-hqoLY`) `[영상]`.

## 이번 주 한 문장

에이전트에 권한이 붙은 자리마다 문제가 생겼고, 그 자리는 대화창이 아니라 설정 파일과 결제 토큰과 재시도 루프였다.

**할 일**

- **오늘** — 저장소의 `.claude/settings.json`과 `.mcp.json`을 훑고, 커밋된 hooks·헬퍼 스크립트·베이스 URL 오버라이드가 있는지 본다. 에이전트 도구는 최신 버전으로 올린다 `[확인: Check Point 권고]`
- **이번 주** — 에이전트가 부르는 툴 중 돈·권한·외부 노출이 걸린 것에 상한과 멱등성 키를 붙인다. 시스템 프롬프트의 금지 문장을 권한 체크로 옮긴다 (`QSCIYtTSe6A`, `hD9-V56FNRI`)
- **이번 주** — 위협 모델 문서의 "입력" 항목에 페이지 본문, 링크 파라미터, 설정 파일, 접근성 트리를 추가한다 (`Dsx4_kCBkbQ`, `eJmF3U0XpyI`, `mlL5vWXEMIU`)
- **이번 달** — 결제나 예약처럼 되돌리기 어려운 동작은 사전 승인 토큰 모델로 옮길 수 있는지 검토한다. 금액·만료·범위를 토큰에 넣고 감사 로그를 남긴다 (`vGn6N4-bxBY`, `[확인: AP2 Intent Mandate]`)

## 용어

**간접 프롬프트 인젝션** / Indirect Prompt Injection
사용자가 아니라 모델이 읽어 들인 자료 안에 지시가 숨어 있는 공격. 웹페이지, 이슈 본문, 설정 파일, 화면 접근성 데이터가 모두 통로가 된다.
> "요약만 시켰는데 curl을 왜 불러요?" "페이지 안에 지시가 있었던 거죠. 간접 인젝션입니다."

**멱등성 키** / Idempotency Key
같은 요청이 여러 번 들어와도 결과가 한 번만 반영되게 하는 요청 식별자. 에이전트는 실패로 보이면 일단 재시도하기 때문에 결제·환불 툴에서는 없으면 안 된다.
> "타임아웃 나면 재시도 도는데, 멱등성 키 없으면 두 번 환불됩니다."

**사전 승인 토큰** / Intent Mandate, scoped token
에이전트가 상품이나 판매자를 고르기 전에 사용자가 조건만 먼저 승인해 두는 방식. 금액 상한, 유효기간, 허용 범위가 토큰에 들어간다.
> "결제 단계에서 사람 부르지 말고, 사전 승인 토큰으로 상한 걸어 두죠."

**양자화 포맷** / Quantization format
같은 비트 수를 표기해도 압축 방식이 다르면 품질·메모리·속도가 달라진다. GGUF, EXL3, NVFP4, AWQ, GPTQ, MLX가 이번 주 비교에 올랐다.
> "4비트라고 다 같은 게 아니에요. 포맷부터 맞춰서 재야 합니다."

**투기적 프로그램형 툴 호출** / sPTC (Speculative Programmatic Tool Calling)
모델이 코드를 다 쓸 때까지 기다리지 않고, 생성 중인 코드에서 툴 호출을 미리 띄워 두는 하네스 최적화.
> "하네스가 토큰 다 뽑을 때까지 놀고 있잖아요. sPTC 쪽 방향이 그겁니다."

## 추천 영상 5편

**`1IbrFrdll4U`** — Checkpoint 연구자가 Claude Code에서 찾은 공급망 취약점을 팟캐스트에서 풀어 설명한다. 핵심은 프로젝트 설정 파일이 저장소에 함께 커밋된다는 점, 그리고 그 파일이 신뢰 확인보다 먼저 실행된다는 점이다. 1차 보고서가 공개돼 있고 패치도 나왔으니, 사고 뉴스로 읽기보다 설계 원칙을 뽑는 자료로 쓰는 편이 낫다. 협업 편의를 위해 저장소에 넣은 설정이 전부 같은 질문을 받게 된다.
