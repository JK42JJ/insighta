# 주간 브리프를 사용자 노트로 — 구조 설계

- 작성 2026-08-26 · 상태 **승인 대기 (미구현)**
- 선행 SSOT: `weekly-knowledge-brief-master-spec.md`(상위 명세) · `newsletter-claim-architecture-2026-08-25.md`(생성 파이프라인)
- 본 문서 범위: 생성된 브리프를 **어디에 담고 어떻게 누적하는가**

## 0. 문제

창간호 CTA 가 `insighta.one/brief/2026-08-25-ai-tech.html` 정적 파일을 연다.
로그인과 무관하고, 지난 호와 연결되지 않으며, 사용자 계정에 아무것도 남기지 않는다.
읽고 닫으면 끝이므로 제품이 아니라 첨부파일이다.

## 1. 실측한 현재 구조

| 확인 항목 | 측정값 | 출처 |
|---|---|---|
| 웹 독립 노트 목록 라우트 | **없음** | `router/index.tsx` 전체 41개 path — `/notes` 부재 |
| 노트 진입 경로 | `/learning/:mandalaId/:videoId` 하나 | 같은 파일 120행 |
| 노트 저장 단위 | `@@unique([user_id, mandala_id])` = 사용자×만다라당 1개 | `schema.prisma` note_documents |
| 노트 생성원 | `mandala_books.book_json`, `based_on_book_version` 으로 stale 판정 | note_documents 주석 |
| 구독 기계 | **이미 존재** `mandala_subscriptions(subscriber_id, mandala_id)` unique | schema.prisma |
| 공개/복제 | `is_public` · `is_template` · `share_slug` · `clone_count` 존재 | user_mandalas |
| 공개 열람 라우트 | `/explore/:slug` 존재 | router 156~157행 |
| 다이얼 탭 | `관심 · 브리프 · 인사이트` 이미 있음 | `mobile/index.html` |

**결론: 노트는 만다라에 종속된 객체다.** 만다라 없는 노트는 이 제품에 존재할 수 없다.
따라서 "노트에 뉴스레터를 넣는다" 는 곧 **"뉴스레터에 만다라를 준다"** 와 같은 말이다.

## 2. 설계 — 카테고리 1개 = 만다라 1개

사용자가 제시한 3층(만다라 / 영상 / 노트)에 그대로 대응한다.

| 층 | 객체 | 주간 동작 |
|---|---|---|
| 만다라 | 카테고리별 공식 만다라 10개 | 고정. 생성 1회 |
| 영상 | 그 주 추천 5편 | 매주 5편 **ADD**(누적, 교체 아님) |
| 노트 | `note_documents` ← `book_json` | 매주 브리프 1개 절 **ADD**, 최신이 맨 위 |

### 2-1. 브리프 본문은 노트가 아니라 book 에 넣는다

노트는 book 에서 생성되는 파생물이고, `based_on_book_version` 이 오르면 재생성 대상이 된다.
브리프를 `content_json` 에 직접 쓰면 **다음 재생성 때 지워진다.**
그러므로 발행은 `mandala_books.book_json` 에 이번 호 절을 추가하고 `version` 을 올린다.
노트는 기존 경로대로 따라온다. 새 렌더링 경로를 만들지 않는다.

### 2-2. 구독 = 클론. 읽기 공유 아님

`mandala_subscriptions` 만 쓰면 구독자는 남의 만다라를 들여다볼 뿐 자기 노트를 갖지 못한다.
`note_documents` 가 `user_id × mandala_id` 이므로, 사용자 소유 만다라가 있어야 사용자 노트가 생긴다.

- 구독 시 공식 만다라를 사용자 계정으로 **클론**(`clone_count` 는 이미 이 개념을 전제한다)
- 주간 발행 = 원본에 1회 기록 후 구독자 클론에 **fan-out ADD**
- fan-out 은 pg-boss 잡으로 처리. 큐는 이미 내구성 확보됨(2026-08-21 확인)

비용은 구독자 수에 비례한다. 베타 규모에서는 무시할 수준이고, 늘어나면 잡 분할로 흡수한다.
읽기 전용 공유(1회 쓰기)로 바꾸면 비용은 줄지만 **사용자 노트가 생기지 않아 본 설계의 목적을 잃는다.**

### 2-3. 링크 3종

| 대상 | 경로 | 로그인 |
|---|---|---|
| 구독자 | `/learning/<clonedMandalaId>/<videoId>` — 자기 노트 | 필요 |
| 공유·미구독 | `/explore/<share_slug>` — 기존 공개 라우트 | 불필요 |
| 모바일 | 다이얼 `브리프` 탭 | 필요 |

메일 CTA 는 구독자 경로로 보낸다. 정적 `/brief/*.html` 은 발행 경로 전환 후 제거한다.

## 2-4. 누적 정책 — 영상은 유한 창, 노트는 영구

주 5편은 연 260편이다. free 카드 한도가 300이므로, 상한이 없으면 **구독 하나가 1년 만에
사용자의 카드 쿼터 전부를 잠식한다.** 정리 규칙보다 회계 분리가 선행 조건이다.

1. **브리프 카드는 `TIER_LIMITS.cards` 에 산입하지 않는다.** 별도 회계.
   구독을 이유로 자기 카드 자리를 잃으면 구독을 해지한다.
2. **지난 호의 글은 노트에 영구히 남고, 영상만 카드에서 내려간다.**
   내려간 뒤에도 노트 본문에 링크로 존재하므로 읽는 경험은 끊기지 않는다.
   텍스트는 저장이 싸고 카드는 fan-out 쓰기 비용과 탐색 비용을 동시에 발생시킨다.
3. 티어 계단은 기존 `curations`(1 / 5 / null)를 그대로 쓴다. 새 계단을 만들지 않는다.

| 티어 | 구독 | 롤링 창 | 살아있는 영상 |
|---|---|---|---|
| free | 1 | 12주 | 60편 |
| pro | 5 | 26주 | 130편 |
| lifetime | 무제한 | 52주 | 260편 |

free 12주는 분기 — 무료 구간에서도 지난 호를 되짚을 수 있는 최소 길이로 James 가 확정(2026-08-26).
pro 26주는 반기 회고에 과거 호를 꺼내 쓸 수 있는 길이다.

4. **내려갈 때는 삭제가 아니라 보관. 사용자가 손댄 카드는 롤링 대상에서 제외한다.**
   노트를 썼거나, 고정했거나, 자기 만다라로 옮긴 카드가 해당한다.
   시스템은 사용자가 만든 것을 지우지 않는다. 예외 없음.
   이 규칙이 없으면 "메모해 둔 영상이 사라졌다" 가 반드시 발생한다.

5. 상한의 근거는 쿼터가 아니라 **탐색성과 fan-out 비용**이다. 1 로 회계를 분리해도
   상한은 여전히 필요하다. 260편이 쌓인 만다라는 고정 칸 구조에서 사용 불가능하다.

현재 코드베이스에 카드 롤링/보관 메커니즘은 **없다**(`prune` 은 관련성 게이트 전용).
따라서 4 는 신규 구현 대상이며 §4 순서의 3 단계에 포함한다.

## 3. 신규로 필요한 것 (이것만)

재사용이 대부분이고 실제 신규는 두 가지다.

1. **`newsletter_issues`** — 발행 원장. 어느 카테고리 몇 호가 언제 어떤 book version 으로 나갔는지.
   없으면 재발송·중복발행·과거호 조회가 전부 불가능하다.
2. **수신거부 토큰** — 로그인 없이 끊을 수 있어야 한다(`GET /u/<token>`) + `List-Unsubscribe` 헤더.
   현재 메일에는 헤더가 아예 없고 본문 링크는 `mailto:` 다.

> **DB 작업은 James 승인 사항.** 위 2건은 제안이며 로컬 포함 어디에도 적용하지 않았다.
> 카테고리 만다라 10개 생성도 데이터 삽입이므로 같은 승인 대상이다.

## 4. 순서

| 단계 | 내용 | 되돌리기 |
|---|---|---|
| 0 | 본 설계 승인 | — |
| 1 | `newsletter_issues` + 수신거부 토큰 DDL (로컬 → prod) | DROP, 기능 미노출 상태라 무영향 |
| 2 | AI·기술 만다라 1개만 생성해 창간호 배선 | 만다라 삭제 |
| 3 | 구독 클론 + fan-out 잡 | flag off = 기존 동작 |
| 4 | 메일 CTA 전환 · 정적 파일 제거 | 파일 복원 |
| 5 | 나머지 9개 카테고리 | 개별 삭제 |

1 단계에서 멈춰도 사용자에게 보이는 변화가 없다. 3 단계까지 가야 연속성이 생긴다.

## 5. 이 설계가 답하지 않는 것

- 카테고리 만다라의 소유 계정을 무엇으로 할지(시스템 계정 신설 vs 대표 계정)
- 구독 해지 시 이미 클론된 만다라를 남길지 지울지 — **남기는 쪽을 권한다.** 사용자가 쓴 노트가 그 안에 있다
- 무료/유료 구독 한도(마스터 명세 §quota 는 별도 트랙)
