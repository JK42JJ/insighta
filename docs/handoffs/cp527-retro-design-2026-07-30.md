## 설계 2 — 원장 게이트 재설계 (★ 최우선, 4연속 실패)

### 왜 현행이 못 잡는가 (실측)

```bash
# init.md 6c-0 현행
LOG=$(newest session-log.md); EV=$(newest eval-scores.md)
[ "$LOG" = "$EV" ] || echo "LEDGER GAP: ..."
```

**두 원장의 최신 CP 번호가 같은지만 본다.** 사후 등재로 양쪽을 동시에 채우면 번호가 일치 → **정상 통과.**
즉 *결손을 메우는 행위 자체가 검출을 무력화한다.* CP522·525·526·527 이 전부 이 경로로 빠져나갔다.

`save.md` Step 10 assert 도 무력하다 — **/save 를 실행해야 돈다.** /save 없이 끝나는 세션에는 정의상 도달하지 않는다. 자기참조 실패.

### 설계: 검출 대상을 "행의 존재"에서 "행의 출처"로 바꾼다

**핵심**: 행이 있는지가 아니라 **실시간으로 쓰였는지**를 본다.

**(a) 행에 출처 필드를 강제**
두 원장 모두 행 끝에 마커 하나. `live` = 세션 중 자기기록, `backfill` = 사후 등재.
사후 등재는 이미 본문에 "사후 등재"라고 쓰고 있으므로 **파싱 가능한 형태로 규격화**만 하면 된다.

**(b) /init 6c-0 을 출처 검사로 교체**

```bash
# 직전 에폭이 backfill 이면 BLOCKING — 번호 일치는 통과 조건이 아니다
last_src(){ grep -E "^\| CP[0-9]+" "$1" | tail -1 | grep -qE '사후 등재|backfill' && echo backfill || echo live; }
[ "$(last_src "$M/eval-scores.md")" = "live" ] || echo "🚨 BLOCKING: 직전 에폭이 사후 등재 — N연속 확인 필요"
```

연속 카운터가 2 이상이면 BLOCKING 질문:
`"원장 사후등재 N연속. (a) 이번 세션은 시작 즉시 행 생성 / (b) 원인 규명 / (c) 공식 포기 — 답 1줄."`

**(c) 근본 해법 — 행을 세션 *시작*에 만든다**
`/init` 마지막 단계에서 두 원장에 **placeholder 행을 즉시 추가**한다(`status: open`).
- 세션 중 갱신, `/save` 가 `status: closed` 로 확정
- **/save 없이 끝나면 `open` 행이 그대로 남는다** → 다음 `/init` 이 즉시 검출
- 사후 등재로 메울 수 없다. 이미 행이 있고 상태가 `open` 이기 때문

이것이 "메우면 통과" 루프를 끊는 유일한 구조다.

### 검증 (적용자가 반드시 할 것)
negative control: `open` 행을 만들고 /save 없이 /init 재실행 → BLOCKING 발화 확인. **발화 확인 전에는 "적용 완료" 금지.** (CP526 watchlist 룰)

## 설계 3 — "이미 있나" 를 재구현까지 확장

### 문제

- 휠 소환: `wz.addEventListener('pointerdown', …cdWheelShow())` 가 이미 존재. James "이미 있는데, 또 만들면서 코드가 개판됐을꺼야"
- 포스터 프로브: `cdBestPoster` 가 `naturalWidth` 로 플레이스홀더를 이미 거르고 있었음. CSS 2겹 트릭을 새로 만들어 회귀 발생

CP519 dead-code LeftPanel 재발과 같은 계열(recurrence 4).

### 설계: CLAUDE.md 추측-전-소스 sub-rule 추가

> **새 메커니즘 작성 前 동일 기능 존재 확인 (CP527 sub-rule)**
> 새 함수·CSS 규칙·상태 관리를 **작성하기 전에**, 같은 파일에서 그 기능의 **동사**로 grep 한다(`summon|show|probe|fallback|retry|resize|relayout` 등). 심볼 이름이 아니라 **하는 일**로 찾는다 — 이름이 다르면 grep 이 빗나가고, 그래서 3함수 거리의 정답을 두 번 놓쳤다.
> 발견 시 **그것을 쓴다.** 못 쓰는 이유가 있으면 PR 설명에 1줄로 적는다.
> 근거: CP527 재발명 2건(휠 소환·포스터 프로브) — 둘 다 같은 파일, 둘 다 새로 만든 쪽이 회귀를 유발.

## 설계 4 — 표면별 룰 신설 중단, 발화 실패를 /retro 필수 항목으로

### 문제
D2 룰이 표면마다 하나씩 늘고 있다: 기기(CP523) · 무료툴(CP524) · 환경재현(CP527) · 측정셋업(CP522) · 추측상수(CP521). **전부 같은 뿌리** — 확인 가능한 사실을 확인 않고 진행.
룰 커버리지 88%, 발화 0%(CP526 실측). 룰이 부족한 게 아니라 **발화하지 않는다.**

### 설계: /retro Step 5 에 필수 섹션 추가

신규 룰 제안 **전에** 아래를 먼저 채운다:

> **발화 실패 분석 (필수)**
> 이번 세션 위반 N건 각각에 대해:
> 1. 이 위반을 막았어야 할 **기존 룰이 있는가?** (있음/없음)
> 2. 있다면 **왜 발화하지 않았는가?** — 읽지 않음 / 이 표면에 해당한다고 인지 못 함 / 인지했으나 무시 / 룰이 기계 게이트가 아님
> 3. **없을 때만** 신규 룰을 제안한다.
> 2번이 "이 표면에 해당한다고 인지 못 함" 이면 → **신규 룰 금지.** 기존 룰의 범위를 넓히거나 기계 게이트로 승격한다.

CP527 에 적용해보면: 위반 "환경 미재현 검증"의 기존 룰 = `feedback_device_verify_no_blind_deploy`(CP523). 발화 실패 사유 = "표면 인지 실패"(그 룰은 '기기'라고 쓰여 있고, 이번은 '설치앱 클래스'였다). → **신규 룰이 아니라 CP523 룰의 범위 확장이 맞았다.**
