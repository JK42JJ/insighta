# 변경 원장 정책 (T / C / P)

> 어느 변경을 어느 원장에 어떤 번호로 남기는가, 그리고 각 항목이 반드시 담아야 하는 것.
> 2026-08-04 신설 (James). 근거는 §0.

## 0. 왜 있는가

**지속적인 리그레션 때문이다.** 검색 품질은 여러 번 무너졌고, 그때마다 "무엇을 바꿔서 이렇게 됐는가" 를 되짚을 수 없었다. T-원장은 그 답으로 만들어졌다 — 닫힌 실험 목록이 아니라 **누적 변수 원장**이고, 되돌아갈 좌표계다.

원장이 하나였을 때의 문제는 2026-08-04 에 드러났다. 큐레이션 검색을 고치면서 하루 종일 진단이 세 번 자리를 옮겼는데(적합도 게이트 → 쿼리 생성 → 수집 파이프라인 정지), **그 셋이 서로 다른 축**이었다. 큐레이션은 PC 에 아직 없는 개념이고, 풀 유입은 전 표면에 영향을 준다. 한 번호 체계에 섞으면 "T14 를 되돌리면 무엇이 돌아오는가" 에 답할 수 없다.

## 1. 세 축

| 이니셜 | 범위 | 원장 |
|---|---|---|
| **T** | 검색 로직 — PC·위저드·add-cards. v3/v5 실행기, 픽커, 게이트, 판정 | `docs/handoffs/version-archetype-matrix-2026-07-12.md` |
| **C** | 큐레이션 — 주간 편성, 구독, 덱. **PC 에 없는 개념** | `docs/handoffs/curation-ledger.md` |
| **P** | 풀 유입 파이프라인 — 수집·태깅·만료. **전역 영향** | `docs/handoffs/pool-inflow-ledger.md` |

**T12 가 T 축의 최종 번호다** (James 2026-08-04). 이후 검색 로직 변경은 T13 부터.

축이 헷갈릴 때의 판정 기준: **"이걸 되돌리면 무엇이 원래대로 돌아오는가."** PC 검색 결과면 T, 주간 편성이면 C, 풀에 무엇이 들어오는가면 P. 둘에 걸치면 **양쪽에 등재하고 서로 링크**한다 — 한쪽만 쓰면 다른 축에서 보이지 않는다.

## 2. 항목이 반드시 담아야 하는 것

롤백과 후속 개선이 목적이므로, **그 항목만 읽고 되돌릴 수 있어야 한다.**

1. **파라미터 / env** — 추가·변경된 전부. `docs/PERFORMANCE_PARAMETERS.md` 해당 행과 상호 링크. 값이 prod 에서 default 와 다르면 그 사실까지.
2. **비용** — 쿼타 유닛/일, LLM 호출/건, 지연. **숫자로.** "비용↓" 같은 서술은 다음 사람이 판단할 근거가 되지 못한다.
3. **로직 변경점** — 무엇이 어떻게 달라졌는가 + **측정값**. 측정 없는 항목은 등재하지 않는다.
4. **롤백 절차** — 플래그 off 인지 revert 인지, 되돌리면 무엇이 남는지(데이터 잔재 포함).
5. **관측** — 배포 후 실제로 무엇이 관측됐는가. 미관측이면 "미관측" 이라고 쓴다. 빈칸은 관측했는데 잊은 것과 구분되지 않는다.

## 3. 번호 부여

- 번호는 **연속**이며 재사용하지 않는다. 철회된 실험도 번호를 유지하고 상태만 `철회` 로 둔다 — 번호가 비면 그 자리에 무엇이 있었는지 아무도 모른다.
- 되돌림은 `-R` 접미사 (예: `T10-R`). 원 항목을 지우지 않고 아래에 붙인다.
- **소급 등재 가능.** 이미 배포된 변경이 번호 없이 지나갔다면 발견 시점에 등재하고 `소급` 을 명시한다. 소급 표기는 "그때 관측한 것" 과 "나중에 재구성한 것" 을 구분한다.

## 4. 가드

`scripts/ci/check-t-ledger.sh` 가 PR 제목/본문에 번호를 요구한다. 스코프에 걸리는 경로를 건드리면서 번호가 없으면 CI 가 막는다.

가드가 존재하는 이유는 스크립트 주석에 적혀 있다 — 판정 트랙이 **2개 PR 을 번호 없이 통과**한 뒤 James 가 물어서야 발견됐기 때문이다. 이 리포에서 기억에만 의존한 규율은 **유지율 0%** 로 기록돼 있다(Rule H/J/A.2). 가드는 유지된다.

**2026-08-04 실증**: 같은 날 큐레이션 검색을 바꾼 PR 3건(#1459 쿼리 생성 · #1462 prod 플래그 on · #1460 북마크)이 **전부 번호 없이 통과**했다. 가드 스코프에 `modules/curation/` 과 `CURATION_` 이 없었기 때문이다. 가드가 틀린 게 아니라 축이 하나 모자랐다 — 이 문서와 C·P 축이 그 대응이다.
