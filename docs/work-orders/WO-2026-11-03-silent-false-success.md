# 목표

"완료"·"성공"·"알림" 신호가 **산출물이 실제로 있는지 확인하지 않고 발화**하는 결함 유형(거짓 성공)을 코드베이스에서 찾아 막는다. 이번 사고(빈 노트 완성 메일, 요약 배치 정지)의 직접 원인을 고치고, 같은 유형이 다른 곳에서 반복되지 않도록 검사와 테스트를 둔다.

# 맥락 (2026-11-03 운영 실측)

## 사고
- 만다라 `AI 데이터 센터 전문가`(18:12 생성, 카드 19장)에서 "노트가 완성됐어요" 메일이 18:14:48에 발송됐으나 노트는 비어 있었다(`mandala_books.chapters = []`, `source_videos = 0`, `source_atoms = 0`). 노트 문서는 문단 하나(51자)짜리 빈 문서였다.
- 최근 14일 노트 완성 메일 3건(10-28 두 건, 11-03 한 건) **전부 `source_atoms = 0`**. 마지막으로 atoms가 있는 노트가 만들어진 것은 10-01.
- 맥미니 요약 배치는 11-02 04:00 이후 매 실행 후보 1~2건, `pass=0`. 후보 1건(`NC9kKtzCygw`)이 10-31 06:27부터 매시간 `prompt_fetch_failed err=unparseable`로 실패하며 "시도함" 표시가 없어 계속 재선택된다. 배치 종료코드는 0.

## 같은 유형이 더 있는지 (코드베이스 진단)
- 알림 발송 지점: 트랜잭션 메일 함수 6종(`transactional.ts`). 노트 완성 메일의 호출 지점은 1곳. 다른 메일은 이번 진단에서 내용 존재 검증 여부를 **확인하지 않음**(P4에서 점검).
- 선점(claim) 후 실행 패턴: 2곳(`mandala-book-fill.ts`, `playlist-sync.ts`). 후자는 다음 실행 시각을 먼저 앞으로 옮긴 뒤 동기화하므로, 동기화가 실패하면 그 주기를 건너뛴다(같은 유형, 영향은 별도 평가).
- 글자 수 절단: LLM·프롬프트·큐 처리 디렉터리에서 `.slice(0, N)` **121건**, 안전 절단 헬퍼는 **0개**(`toWellFormed` 등 사용 흔적 없음).
- 알려진 동일 유형 선례: `CP515` PWA 서비스 워커가 확장자 없는 경로의 주소창 입력에 SPA 404를 서빙(이번 `/survey/` 404가 두 번째 발생, 아래 P6).

# 제약

- 코드 변경은 이 작업지시서 승인 후에만. 운영 데이터 변경(claim 초기화, 재처리)은 스냅샷과 롤백 방법을 먼저 확보하고 별도 승인.
- 맥미니 스크립트는 저장소가 추적하지 않는다(체크아웃이 2026-05-07 커밋에 수정본이 얹힌 상태). 수정 전에 현재 상태를 백업하고 James 승인.
- 같은 파일을 다시 여는 항목은 한 PR로 묶는다. 자동 배포 구조상 main 머지는 운영 DB·Edge Function에 즉시 영향이 있으므로(R33 공백) 변경 범위를 작게 유지한다.
- 의존성 업그레이드나 다른 기능 변경을 섞지 않는다.

# 순서

각 단계는 별도 PR이며 단계마다 검증 기준을 통과해야 다음으로 간다.

1. **P0-a 안전 절단**: 코드 포인트 안전 절단 헬퍼(반쪽 서로게이트 제거)를 만들고 `rich-summary-v2-prompt.ts`의 5개 `.slice`에 적용. 이모지가 경계에 오는 입력의 회귀 테스트와, 직렬화 결과가 엄격한 JSON 파서를 통과하는지 확인하는 테스트.
2. **P0-b 빈 노트 알림 차단**: `fillMandalaBook`이 atoms 수와 chapters 수를 결과에 포함. 알림은 `source_atoms > 0`이고 `chapters` 비어 있지 않을 때만. claim은 **내용 확인 뒤** 생성(빈 빌드는 claim 안 함). 회귀 테스트(atoms 0이면 메일 안 감, 나중에 atoms가 생기면 한 번 감).
3. **P1 완료 정의 정렬**: 장벽의 "완료"를 "행 존재"가 아니라 "노트 재료(atoms)를 가진 v2 도착" 또는 "더 기다려도 atoms가 생기지 않는 영상 확정"으로 변경. 화면은 빈 노트일 때 "노트 생성 중" 상태 표시. 설계안 검토를 먼저(비용·대기 시간 영향).
4. **P2 재처리**(데이터 변경, 별도 승인): 이미 빈 노트를 받은 만다라 3개의 영상을 도메인 필터 없이 대상 지정 배치로 처리, 처리 후 노트 재빌드, 해당 만다라의 claim 초기화로 정상 알림 1회. 사전에 스냅샷(대상 행의 `video_rich_summaries`, `mandala_books`, `note_ready_email_sends`)과 롤백 SQL 확보. P0-a 배포 이후에만 실행.
5. **P3 맥미니 스크립트**(승인 후): JSON 파싱 실패 포함 실패 N회 연속 시 `mark-attempted`, 종료코드를 결과 수 기준으로, `transcript-svc`와 Ollama 로그 경로 복구. 스크립트를 저장소에서 추적하도록 정리.
6. **P4 감지**: Keel 검사 4개(알린 노트 중 빈 것, 배치 `pass=0` 연속, 후보 수 하한, 서비스 로그 신선도)와 알림 채널 연결. 다른 트랜잭션 메일 5종의 "내용 존재" 점검.
7. **P5 전수 정비**: 121개 `.slice(0, N)` 중 JSON·LLM 프롬프트로 흘러가는 것을 분류해 헬퍼 적용. 재발 방지용 검사(린트 규칙 또는 단위 테스트).
8. **P6 `/survey/` 404 (별도 PR, 프런트 변경)**: `navigateFallbackDenylist`에 `/^\/survey(\/|$)/` 추가. CP515의 두 번째 발생이므로 확장자 규칙만으로 부족한 경로를 정적 페이지 목록으로 관리하는 방식도 검토. 프런트 변경이라 푸시 전 `/verify` 필요.
