## 스크린샷 — 미제작

Play 는 휴대전화 스크린샷 **최소 2장**을 요구한다(16:9 또는 9:16, 최소 320px).

**실기기 촬영을 권한다.** 앱이 로그인 벽이라 로그아웃 상태로는 로그인 화면밖에 못 찍고,
그것은 스토어에 올릴 화면이 아니다. 실제 데이터가 들어간 화면이어야 한다.

찍을 화면 4장 제안 — 앱의 세 탭을 한 번씩 보여주는 순서:

1. **관심** — 주간 편성 목록이 채워진 상태
2. **브리프** — 영상 재생 + 관련도 마운드가 보이는 화면
3. **인사이트** — 노트가 열린 화면
4. 다이얼(조그휠)에 손이 닿아 있는 상태 — 조작 방식이 한 장으로 설명된다

## 심사 노트 (Console → 앱 콘텐츠 → 심사자용 정보)

**필수.** 앱이 로그인 벽이라 계정 없이는 심사자가 아무것도 볼 수 없다. 게스트 경로는
공유 링크 토큰 전용이라 일반 둘러보기가 되지 않는다(`/api/v1/guest/<token>/...`).

```
이 앱은 로그인이 필요합니다. 아래 계정으로 접속해 주세요.

이메일: <심사용 계정>
비밀번호: <비밀번호>

로그인 후 하단 다이얼을 돌리면 목록이 넘어가고, 가운데를 누르면 재생됩니다.
상단 탭 세 개(관심 / 브리프 / 인사이트)가 각각 주간 목록, 영상, 노트입니다.
```

**심사 전에 이 계정에 실제 데이터를 채워 둘 것.** 빈 계정으로 로그인하면 심사자는
빈 화면을 보게 되고, 그것은 기능 부재로 읽힌다.

## 데이터 안전 (Console 설문) — James 작성

CC 가 대신 답할 수 없는 항목이다(사실 신고이며, 틀리면 정책 위반). 답하기 전 확인이
필요한 것만 적어 둔다.

| 질문 | 확인해야 할 사실 |
|---|---|
| 수집하는 데이터 | 이메일(계정) · 사용자가 만든 목표·노트 · 시청 위치 |
| 제3자 공유 | Supabase(인증·DB) · YouTube(영상 재생) · OpenRouter(요약 생성) |
| 암호화 전송 | HTTPS 전 구간 — 사실 |
| 계정 삭제 경로 | **있음 — 실측 완료** (아래) |

**계정 삭제는 이미 구현돼 있다.** 실측(2026-08-13):

- `DELETE /api/v1/settings/account` — prod 에서 무인증 호출 시 **401**(존재하고 보호됨).
  라우트 정의 `src/api/routes/settings.ts:106`, 주석에 *"Delete all user data from DB"*.
- 앱 내 진입점 = 설정 화면(`SettingsPage.tsx:216` → `apiClient.deleteAccount()`).

Play 는 데이터 안전 신고에 **앱 밖에서도 닿는 삭제 요청 URL** 을 요구한다.
`https://insighta.one/settings` 로 답하면 된다 — 웹에서 같은 계정으로 로그인해 실행할 수 있다.

남은 확인 하나: 삭제가 **어디까지 지우는지**(계정만인지 노트·시청기록까지인지)를 신고
문구와 맞춰야 한다. 라우트 주석은 "all user data" 라고 하지만, 신고는 코드가 아니라
**실제 동작** 기준이어야 하므로 James 가 테스트 계정으로 1회 실행해 확인하는 편이 안전하다.
